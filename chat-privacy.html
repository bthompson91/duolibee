Account and Chat data use — v0.34.0

Effective 25 October 2026. This supplements the main privacy policy. For learning-progress erasure see the reset notice.

Account and eligibility

Google sign-in supplies identity for Chat. Google separately grants Drive app-data permission for learning-progress backup. Tokens remain in browser memory, not deliberately in localStorage, chat records or cloud saves. Signing out does not erase history. Chat is offered to adults aged 18+ using it in Australia. The checkbox and Google sign-in do not verify age or location. Untick Chat if eligibility changes. Unticking stops new browser requests, not already accepted server work.

One continuous Bee thread

The server keeps one ongoing transcript per account. Existing account-owned legacy conversations are copied into the transcript once, without deleting the original records. The interface automatically starts a lesson exchange, adds qualitative feedback when it ends, and opens the next exchange in the same thread. After lesson 100 it cycles to lesson 1 for practice. Chat progression does not award XP, hearts or lesson completion.

End-of-exchange feedback is generated locally from stored assessment ratings, relevance and hint use; it is an estimate, not an independent language examination. The current lesson and a short recent context from the previous exchange are sent for new assessments, not the entire accumulated history.

Gemini and stored data

Assessed replies, recent messages, vocabulary, mission goals and instructions go to Google Gemini. Under unpaid-service terms, content and outputs may be reviewed by humans and used to improve Google products. Use fictional details only; do not enter sensitive or confidential information, credentials, health or financial data. See Google's terms. No paid-provider/model fallback is implemented. Local request caps are not a billing guarantee.

The VM stores account identifiers, transcripts, ratings, hints, evidence, usage counters and cached replies in SQLite. Logs may contain IPs, paths, times and status codes. The browser stores the Chat visibility preference and account-scoped drafts/pending-send details in sessionStorage for retry recovery; these drafts are not sent to Drive. Clearing browser data does not erase server history.

Retention, limits and erasure

The continuous thread and its active backing session are retained until you erase the thread; they are excluded from the legacy seven-day inactive-session cleanup. Earlier messages are loaded in pages, not discarded. Old legacy sessions remain subject to their existing cleanup when legacy session creation runs.

The production configuration installed with the cap repair allows 400 assessment attempts per account per UTC day and 10 per minute; shared caps are 450 per UTC day and 12 per minute. Operator configuration can differ. Failed provider calls count. Google and web-server limits also apply. Continuous lesson exchanges reuse a backing session and do not create a new saved conversation for each lesson.

Choose Erase this thread in Chat controls to remove the continuous transcript, its active practice session and its thread request cache from the live database. It does not erase imported legacy originals, usage counters, manual backups or provider records. The import marker remains so erased legacy copies are not immediately re-imported.
